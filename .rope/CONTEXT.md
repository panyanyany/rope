# 项目上下文

<a id="language"></a>
## 项目语言

**Parent Orchestrator（父编排器）**：
负责一个 issue 的主会话，也是唯一可以为该 issue 派生工作者的代理。职责包括需求澄清、切片规划、叶子派发、issue 级验证和 finish 交接。

父编排器负责决策、用户交流、长期文档和简报。它通过修改简报、重新派发叶子来纠正实现，不批量加载探索轨迹，也不自行执行长时间实现与修复。这样可以减少上下文压缩造成的早期决定丢失。
_避免_：含混的主会话、上帝代理、代理群、纯路由器、父编排器包办实现。
_历史别名_：Planner Window / Window A，属于可选部署方式，不是架构本身。

**Leaf Worker（叶子工作者）**：
接收自包含简报、做一件事、返回摘要和产物路径的子代理或宿主工作者。实现、审查、探索都属于叶子角色；父编排器重写简报后的纠偏也由叶子执行。叶子不能再派生工作者。
_避免_：嵌套子代理、子编排器。
_历史别名_：宿主不能派写代码子代理时，降级独立主会话称 Implementer Window / Window B。

**Human Escalation Stop（人工升级停止）**：
叶子修复无进展，或父编排器判断属于设计 / 需求 / 契约问题而非实现遗漏时，停止自动修复，给用户简短准确的问题说明并请求决定。当前无进展标准见 ADR 0007：全新叶子重复相同失败特征，或审查 / E2E / verify 的阻塞集合不再缩小。
_避免_：无限修复、静默重试、用更多补丁掩盖设计冲突。

**Harness Profile / Role Preset（宿主角色预设）**：
将 Rope 叶子角色绑定到宿主原生代理模板的配置。运行模型识别宿主，探测注册机制和模型目录，再写入 pi Markdown+frontmatter、codex TOML 等原生格式。技能中不硬编码宿主适配分支。

预设默认写入用户级代理目录。用户全局清单只记录角色、预设名、模型和生成信息，不放入项目 `.rope/`。预设仅手动刷新，没有 TTL。原生预设是派生配置的来源，Rope 不另建完整提示或工具数据库。explore 不限制宿主工具；默认只读及调研时仅写 `.rope/research/**` 的限制由预设正文规定。
_避免_：技能硬编码模型表、provider 锁定、影子运行时、默认提交机器私有模型目录、自动刷新、按宿主写分支。

**Issue-Level Verify（issue 级验证）**：
go 完成后、finish 收尾前的记录检查，目前由 finish 第一阶段执行。它核实结束审查是否运行、结论及身份和修复轮次是否记录、E2E 是否都有终态且没有分类漂移、切片是否已提交、工作树是否干净，以及架构文档更新是否已安排。

verify 不重新判断代码或产品。它只能依据已经核验的证据补齐 issue 记录。
_避免_：第二次代码审查、重跑已绿测试、无身份的结论声称。

**End-of-Issue Review（issue 结束审查）**：
全部切片完成后的唯一代码审查。父编排器确认全部切片已合并、工作树干净且没有活动叶子后，在同一消息中并行派发两个未参与实现的只读叶子。

规范扫描器先运行 lint/typecheck，再根据仓库规范、TDD 反模式、代码异味基线及全局不变量检查组装 diff，不运行产品。行为审查者对照行为矩阵检查组装 diff，并深入检查高风险边界。审查返回 approve 后，才进入产品启动、真实入口操作和 E2E 验收阶段，见 ADR 0015。

父编排器按固定规则取两个维度中较差的结论，不重新判断或排序。每项发现标记为 blocking 或 note，并附 path:line 及一句修复建议。只有 blocking 进入统一修复简报；阻塞集合不再缩小时，停止自动修复并交给用户决定。复审只看修复差量，不再逐片审查。
_避免_：混淆审查层级、逐片结论记账、静默自审降级、只靠 fixture 验收、父编排器重排轴、扫描器运行产品、审查者重走 runner 已证明旅程。

**Standards Scanner（规范扫描器）**：
结束审查中的低成本只读叶子。先跑简报的 lint/typecheck/build，跳过工具已保证项，再依据仓库规范、TDD 反模式、Fowler 异味基线及全局不变量快扫 diff。每个命中需判断，仓库规范优先。由 explore 预设加内联基线派生，返回 clean 或 ≤200 词的 severity/path:line/issue/fix。端口、进程归后续父编排器服务栈及 E2E runner。
_避免_：扫描器做深度判断、把启发式当硬违规、将架构连续性判断移出行为审查者。

**Graph-Driven Execution（依赖图驱动执行）**：
根据切片及其真实依赖安排执行。shape 采用 tracer-bullet 切片，以真实阻塞边和单个全新上下文窗口的容量为硬约束。组件切片和前置重构可以单独存在，不要求每片都包含完整用户旅程。切片形成后，展示初始就绪数、各层宽度和最长阻塞链，再提出一次包含这些数据的执行选择。

go 默认将就绪切片并发派发到后台；串行执行必须记录原因。启动时说明计划并行度和最大并行度。worktree 模式为每个叶子提供独立目录：seam-required 依赖合并后即可派发，file-overlap 只表示合并顺序偏好。父编排器按顺序合并，并维护 map；routes 声明 worktree 准备契约。

shared 模式按拥有文件不相交的切片分波次，由叶子维护各自范围内的 map。由于共享索引和检出目录，提交必须串行。当前流程没有 mode/review frontmatter，忽略旧包中的这些字段。重新拆分会改变需求时，返回 grill。
_避免_：worktree 波次屏障、图未成就问串并行、并行合并、逐合并测试仪式、并发写共享 map。

**Delivery Branch（交付分支）**：
worktree 叶子用于交付最终提交的分支，名称由简报预先声明。返回前，叶子必须提交全部工作，确认 `git status --porcelain` 为空，再运行 `git branch -f <delivery branch> HEAD`，将交付分支指向最终提交。

父编排器从 git 核验 SHA，不依赖口头声称，也不从自由文本猜测分支名。宿主用于清理的 pi-agent 分支不得作为合并路由。
_避免_：解析散文分支名、信任口头 SHA、路由到 pi-agent-*。

**E2E Runner（端到端执行者）**：
规范和行为审查均批准后，通过真实产品入口执行一条用户旅程的叶子工作者。入口由项目声明，可以是浏览器、消息通道、CLI 或 API；Rope 不指定工具。注入和 fixture 只能作为集成证据，不能代替真实入口。

父编排器负责一套共享服务栈，声明启动命令、探测就绪，并在结束后关闭。runner 不自建服务栈。资源不相交且会话隔离时并行；共享账户或可变状态时串行。runner 不修改代码，不派生代理，按结构化格式返回步骤、命令、产物和逐项结果。

每个必需项都必须有 agent_passed 或 user_confirmed 证据，或有用户逐项明确豁免。豁免不得记作通过；其他情况保持阻塞。修复后，对代码差量复审，在新 HEAD 重新部署，并重跑受影响旅程和共享入口冒烟测试。复用证据必须注明对应提交。
_避免_：实现者自签验收、审查者重复旅程、每 runner 一栈、把注入当真实入口、静默吸收豁免。

**Self-Fix Loop（自修复循环）**：
源自 Trellis 的检查模式：验证模型发现问题后直接修，再检查至通过。Rope issue 验证不使用，因为实现与验收角色分离，verify 不改代码。
_避免_：含混的自动修复、重试。

**Escalation（升级检查）**：
验证模型自行判断发现需更深入检查，通过继续阅读或派只读 explore 完成；由判断驱动，不靠机械触发器。
_避免_：带机械含义的 upgrade/promote。

**Upstream Harvest（上游灵感采收）**：
本仓维护流程：比较固定外部灵感来源与上次已审版本，生成面向人的变更简报，经接受 / 改造 / 忽略决定后才落入 Rope 原生技能或知识层。初始来源 Matt Pocock，可选 Trellis。不由 rope add 分发，不自动合并 vendor。
_避免_：与复制混淆的同步、只描述机制的子模块更新、已退役的一次性迁移桥。

**Acceptance Behavior（验收行为）**：
工单或 issue 承诺的用户或调用者可见结果。按 ADR 0009 分层：ticket-TDD 在 shape 确认的测试边界上执行 red→green；issue-BDD 用行为矩阵说明整体行为，不能用切片索引代替行为规范。

真实入口操作由 E2E 阶段执行。e2e.md 只记录必须在真实环境中证明的行为。covered_by_slice 已删除；能够仅由切片测试证明的条目不属于 E2E。
_避免_：先写大堆单测再编码、把验收等同文书 verify、默认验证时重跑全部绿单测。

**Architecture Impact（架构影响）**：
shape 按条件记录 issue 是否触碰已有决策、公共边界、依赖方向、生命周期、状态、持久化、权限、并发、错误语义、adapter、运行入口或重复职责。not-applicable 也需轻量检查，存疑按需解决处理。
_避免_：每任务完整架构审查、仅凭文件名 / diff 推断、自动要求新 ADR。

**Decision Disposition（决策处置）**：
逐决策说明本 issue 如何处理已有架构：inherit、extend、supersede、exception、not-applicable。与来源本身 active、superseded、deprecated、provisional、unknown 状态不同。
_避免_：多决策共用一处置、实现中默选、把例外当无文档捷径。

**Constraint Bundle（约束包）**：
切片前从生效来源推导出的架构约束集合，包括来源及状态、范围、不变量、公共边界、禁止的实现捷径、所需证据和冲突。

父编排器保留完整约束包。每个切片和简报必须列出适用的全局及局部约束 ID，以及必读章节。不适用时，明确写出 none 及理由。生效来源优先于局部实现便利；发现冲突时交回父编排器处理。
_避免_：一句“遵循 ADR”、有 ID 无阅读、叶子局部重新解释、第二份权威架构文档。

**Architecture Landing（架构落点）**：
实现者读取映射章节后、编辑前写下的不超过 3 行声明。说明复用的已有职责、使用的公共边界，以及保留的职责归属和依赖方向。

返回时附已读章节及编辑前记录的引用。返回检查只核对证据，结束审查负责判断是否符合约束。该声明不增加批准轮次。
_避免_：复制 spec、逐文件计划、把事后记录冒充编辑前阅读。

**Contract Note（契约摘要）**：
shape 将行为契约投影给用户，3–5 个单句回答“完成后能观察到什么”，适用时说明失败可见性。写 prd.md 的 `## Contract Note`，用户确认摘要即确认所投影的契约，无需默认通读 PRD。验收仍依据行为契约、矩阵、E2E；摘要不是另一份愿望或独立验收产物。
_避免_：第二份易漂移契约、默认要求用户读全 PRD、把摘要作为验收证据。

**Minimal Leaf Brief（最小叶子简报）**：
按允许清单编写的叶子任务说明。内容包括一句 Public behavior、最简六字段契约、约束包路径、适用的全局及局部 ID、简短全局不变量、测试边界和一个先例路径。

必需操作契约另外列出编辑前必读来源、架构落点证据、产物及 map 路径、TDD 红绿命令和失败信号、返回格式、禁止嵌套派生及提交规则。其余内容通过引用加载。简报正文不超过 60 行，路径和命令块不计入；派发前可以检查。
_避免_：内联 PRD / 包细节、推测逐文件计划、为省词删 TDD 命令或返回格式。

**Investigation Map（调查图）**：
位于 `<issue>/map.md` 的共享定位记录，由 shape 根据探索结果初始化。每行记录一个事实、来源路径和日期。

shared 实现者在提交前修正各自范围内被证伪的条目。worktree 叶子在摘要中返回修正，由父编排器在每次合并后写入，避免并发修改共享文件。失去定位价值的条目可以删除。
_避免_：倾倒对话、无说明的旧事实、简报内联整图。

**Quick Fix Path（小任务快速路径）**：
rope-quick 由单个代理完成能够装入一个全新上下文窗口的已诊断修复或小功能。先通过 grill-lite 核验事实、完成一轮决策并写入 quick.md，再在最近的测试边界执行 red→green 或测试先行，最后本地提交并同步知识层。

该路径不建完整 issue 包，不派叶子，也不做 issue 级 verify。用户负责验收，收尾报告提供需要人工关注的风险位置。出现新架构决策、同一修复失败两次、范围扩散，或 schema、破坏性及生产操作时，停止快速路径，在 quick.md 标记 stopped，并返回完整流程。
_避免_：任何 issue 都用 quick、未经确认就接受新决定、无 red 只报绿、额外入口限制、需要第二轮仍不停。

**Plan Artifact Reader Layering（计划产物读者分层）**：
针对不同读者安排交接内容。用户阅读 grill 的 3–6 点回顾和 Contract Note 的 3–5 点摘要；执行代理按引用读取契约、矩阵、约束包和任务。

能够解决的问题应在 shape 前的 grill 阶段确定。go 叶子发现冲突后交回父编排器，重新确定处置并修改简报，不自行接受冲突。该规则取代“计划简洁、最后列未解问题”的旧做法。
_避免_：一个格式服务所有读者、带未决问题执行、未经处置就接受叶子发现的冲突。

**Edge Classification（边分类）**：
shape 为每条 Blocked by 依赖边标记 file-overlap、seam-required 或 methodology-order。

seam-required 在两种模式中都阻塞派发。file-overlap 在 shared 模式阻塞派发；已核实的 worktree 模式中，它仅表示合并顺序偏好，允许从共同基线并发实施，再按顺序合并。未合并分支发生冲突时，可以重新派发一次。methodology-order 不涉及文件重叠或接口依赖，只表示更易理解的顺序，不阻塞派发。
_避免_：把“串行更安全”当依赖、无标签引回波次、无文件事实标边、降级尚不存在的必要边界依赖。

**Two-stage Contract Slice（两阶段契约切片）**：
涉及深层持久性、并发或协议的 Kind: contract 工作，必须拆成接口和独立加固两个阶段。接口阶段提供消费者可依赖的公共边界及最小操作；加固阶段处理崩溃恢复、并发协议和深层净化。消费者只依赖接口阶段，不等待加固阶段。

迁移文件必须有唯一归属。
_避免_：将接口与存储状态机加固放在同一切片、让加固返工阻塞消费者关键路径、两片拥有同迁移。

**Mechanical Return Gate（机械返回检查）**：
将叶子返回结果与切片 Required evidence 逐项核对的过程。检查项包括来源阅读、编辑前架构落点、受影响检查和例外差异。每项要求都应对应实际输出、产物路径或消息引用。

缺项时，只退回对应证据 ID。发现架构冲突时，暂停相关合并。父编排器不读取实现来重新审查，不重跑测试，也不增加验收点；issue 结束审查仍是唯一代码审查。
_避免_：父编排器落地时读实现、重跑叶子测试、借检查新增验收。

**Defense Budget（防御预算）**：
限制修复范围的规则：纠偏简报不得在 shape 已确定的行为矩阵和约束包之外增加验收要求，新增数必须为 0。架构义务必须在 shape 声明。

执行中发现真正的契约缺口时，返回 shape 重新拆分，或记录为非阻塞备注。不得通过每轮增加约束来扩大修复范围。
_避免_：执行中膨胀验收、只在修复出现防御要求、轮次间约束漂移。

**Granularity Quiz（粒度确认）**：
依赖图形成后，与图确认一起检查切片是否过粗、过细、依赖边是否真实，以及是否需要合并或拆分。用户确认切片粒度和波次。

每片都应有可演示行为，不能只写一个层名。能够在单个上下文窗口内完成的改动，直接推荐 quick，不建多片 issue。
_避免_：另开串行问答轮、演示路径写层名、为显严谨拆小改动。

**Human Gate Panel（人工授权面板）**：
将多个待人工决定或批准的事项集中展示的格式。每项说明受影响切片、请求批准的具体动作和影响范围，并说明其他尚未获授权的工作线是继续还是暂停，避免逐项阻塞全部工作。
_避免_：其他线空等、含混授权需再追问才懂。

**Research Floor（调研底线）**：
ADR 0017 规定的最低调研要求。涉及新机制、外部集成或成熟产品做法判断时，必须在决策轮次前并行调研，通常分别调查仓库先例和外部产品。纯内部小改动记录 research: not-needed 及理由。shape 必须检查调研引用或豁免；两者都没有时，不接受 PRD。

自建前依次检查需求必要性、仓库先例、标准库和平台能力、已有依赖，最后才设计最小自建方案。未经核验的行业实践说法不能作为决策依据。
_避免_：把“优先调研”当可跳过、把模型记忆当先例、用底线阻碍无需调研的 quick。

**Dispatch Contract（派发契约）**：
ADR 0017 规定的交接规则。简报是可执行契约，必须声明问题、来源、输出路径和返回格式。叶子无法完成某项要求时，在 unknowns 中说明该项及已尝试内容，不得省略。

规则指定由叶子执行的工作必须派发，包括 E2E、调研和修复。go 和 E2E 阶段的父编排器不修改产品代码或测试；需要纠正时，修改简报并重新派发，不接管失败叶子的实现。
_避免_：把接管包装成改简报、空返回算通过、返回时默缩范围。

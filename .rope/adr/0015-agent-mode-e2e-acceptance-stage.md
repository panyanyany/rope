# 0015 代码审查后的独立 E2E Runner 验收阶段

**状态：**active。agent 派发下部分替代 [0010](0010-parallel-two-leaf-end-of-issue-review.md)第 2 条产品运行独占，扩展 [0007](0007-graph-driven-go-single-review.md)：保单审查点，真实入口移独立阶段。0016 后 dynamic 退役，本阶段为唯一 E2E 路径。用户 2026-09-23 决定不改 quick。

日期：2026-09-23。

<a id="decision"></a>
## 决策

完整 issue 流程：切片集成 → 双轴代码审查 → approve → E2E → 必需旅程有证据通过或明确豁免 → verify。

1. 行为审查者不再运行产品。保双并行只读叶子、机械汇总、二级严重度、差量复审；原始最多两轮后由 0007 无进展规则修订。审查者按矩阵审 diff 和高风险；端口 / 进程 / 浏览器归 E2E。
2. 新只读 runner，每叶子一条**项目声明真实入口**旅程。浏览器、真实消息、CLI、API 由 routes / Testing Decisions 定，Rope 不指定工具。注入、fixture、单元通过只是集成证据，不能代替。runner 不写代码、不派生，返回步骤、工具 / 命令、产物、逐项结果。
3. 父管一套共享栈：项目启动命令、派发前就绪、最后关闭。runner 不自建。资源不相交、会话隔离 / 数据独立并行，共享账户或状态串行，无宿主隔离则记理由后串行。
4. 必需 E2E 均有 agent_passed 或 user_confirmed，否则阻塞；仅可用逐项明确用户豁免代替，豁免 / blocked 不得写通过。按宿主实际能力执行所有工具覆盖机制。
5. 失败原样入实现者简报，防御预算不变。原两轮后停规则现按 0007 无进展。合并后差量复审、新 HEAD 重新部署、受影响旅程及共享入口冒烟重跑，复用证据注明原提交，旧 HEAD 通过不能冒充当前。

<a id="context"></a>
## 背景

2026-09-16–23 调研发现验收执行者漂移：主窗口、审查自建栈、quick 内联、仅无头。clear 修复以注入标 E2E PASS 却无真实钉钉入口；legal-finance E4 Admin 阻塞却关闭；模型管理父 / 审查各启一栈。Matt 上游无独立 E2E 角色 / 共享栈先例，社区 #397 同样服务绿却 UI 缺失，未有已发布策略。此设计是回应 Rope 现场问题的自有选择。

<a id="why-this-shape"></a>
## 理由

代码缺陷与真实环境 / 入口真实性是不同失败类，混同一叶子会让昂贵阶段受廉价阶段阻塞，也易把代码绿当产品绿。一栈去除重复启动和端口 / 账户争用，隔离旅程并行省时。机制分类已有，本阶段负责落实。

<a id="consequences"></a>
## 后果

- 阶段归 go 执行规则，不设独立技能。reviewer 预设缩只读代码，安装再生成时更新。
- runner 为有意新增第四角色，更新角色、模板、清单，再生成对应原生文件。
- go→verify 增阶段结论前提，用户当时决定不改 verify/finish 职责；verify 仍文书 / 防漂移，旧产品判断指向审查者的引用已修。
- 接受多一阶段、无法就绪则阻交付直到豁免，以及无会话隔离串行变慢的成本。

<a id="alternatives-considered"></a>
## 考虑过的方案

保审查者跑 E2E：现场漂移证据反对。多审查者走旅程：混判断与运行或丢审查轴。实现者自验：自评偏乐观且违跨角色分离。runner 各建栈：已有重复成本和资源争用。均拒绝。

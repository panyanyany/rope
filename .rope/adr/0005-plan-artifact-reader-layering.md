# 0005 计划产物读者分层

计划有两类注意力预算不同的读者：人用几句话确认意图，机器即父编排器和叶子按引用读结构化契约。面向人的 grill 回顾、Contract Note 保持精简；机器用行为契约、约束包；未决问题执行前解决，不由叶子默吸。本决策扩展 ADR 0004 的引用加载及父上下文节制，不改审查模式，而明确可测量的简报内容与用户确认规则。

<a id="context"></a>
## 背景

- 用户少读完整 PRD，但验收依据其行为契约；只确认聊天回顾而 PRD 漂移，可能接受用户从未想要的结果。
- 已有引用加载，却无内联内容预算，“简洁”只是偏好。
- 上游“简洁计划、末尾列未决问题”缺读者模型、预算、执行中新问题处理，不够 Rope 原生。

<a id="decision"></a>
## 决策

1. **读者分层：**人读 grill 3–6 点回顾、shape 3–5 句可观察结果摘要；通俗易扫读。机器按引用读契约、矩阵、约束包、任务，不批量复制聊天 / 简报。
2. **契约摘要：**shape 在 prd.md 写 `## Contract Note`，3–5 句说明完成后可观察结果，相关时含失败可见性。用户确认摘要而非默认读全 PRD；摘要直接投影契约，确认即确认契约，不另列愿望。验收仍依契约。
3. **最小简报预算：**允许内联一句 Public behavior、最简六字段、包路径及切片 ID / 短全局不变量、测试边界及一个先例。必需操作契约另含引用路径、红绿命令 / red 信号、摘要 / 路径 / 提交返回、禁止嵌套 / 提交规则。切片备注、PRD 段落、包细节、实现笔记、逐文件推测计划只按引用读。正文 ≤60 行，路径 / 命令块不计。
4. **未决问题：**可回答的在 shape 前 grill 解决，不带作实现分支。go 叶子冲突返回父编排器处置，不默吸、不自造 exception/extend/supersede。新规则是 shape 前解决、发现时重简报。

<a id="why-this-split"></a>
## 理由

- 人与机器注意力预算不同。Anthropic 上下文工程强调小而高信号集合，Addy Osmani 建议摘要 / 目录和引用读取；契约摘要是面向人的对应机制。
- 确认必须绑定验收产物，摘要存 PRD 可审计、可追溯，避免聊天回顾漂移。
- 允许清单和 ≤60 行可检查，“简洁”无法测。
- 叶子自造处置或吞问题可能片测通过却违背意图，重简报把决策留在负责层。

<a id="consequences"></a>
## 后果

- shape 输出摘要 → 用户确认 → 提交包，不默认要求通读 PRD。
- go 简报按允许清单和行数，叶子按引用加载细节。
- 验证仍基于契约 / 矩阵 / E2E，摘要仅辅助确认。
- 旧包无摘要仍兼容，新包必须写。
- ADR 0004 的引用约束和父上下文节制不变，本 ADR 收紧内联内容。

<a id="considered-options"></a>
## 考虑过的方案

- 严格只留四项内容：拒绝，省掉红绿命令、返回、纪律会破坏验收循环及父核验能力。
- 摘要独立文件：拒绝，增同步成本；嵌入 PRD 保持唯一来源。
- 合入 ADR 0004：拒绝，审查频率 / 成本与读者分层是独立决策。
- 无数字预算：拒绝，不满足明确预算要求。

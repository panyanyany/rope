<a id="rope-clear"></a>
# Rope Clear：文档整理

整理项目知识，让读者能从当前入口找到有效规则。范围包括修订、迁移和去重文档，以及将旧 `.rope/CONTEXT.md` 迁移到 `.rope/GLOSSARY.md`。只修改文档，保留产品行为和既有架构决定。初始化目录仍由 init 负责。

写入说明、简报或记录时，遵守[中文文档写作规则](../rope-grill/references/content-design.md)。

<a id="workflow"></a>
## 工作流程

1. **限定范围：**读仓库指令和 routes，按[现行文档契约](references/current-docs.md)识别术语表及目标路径。按需读取定义和来源章节。检查 git 状态，区分已跟踪、已修改、未跟踪、外部 / 已安装文件。默认只处理本仓库的 `.rope/`。将必要的入站链接修复列入批次，包括根代理指令中的链接；其他范围扩展需要用户同意。把范围写入现有工作记录。完成本步前，必须明确每个候选文档的归属和保留要求，并完整保留用户编辑。
2. **确认当前事实：**先读现行文档契约。未知来源 / 用法按[交接契约](../rope-harness-presets/references/role-schema.md#exploration-and-validation-handoff)交 explore，要求范围内事实、归属、入链、证据及未知项；父编排器决定批次和语义冲突。逐项检查候选文档的状态、范围、明确的取代关系、相关源码和测试，以及 Git 历史。同时检查是否需要执行下述旧术语表迁移。分类为保留、修订、迁移、去重、退役引用、未解决。文档年代、内容重复和文件名只能作为调查线索。完成本步前，每项提议都必须有证据，或列出尚待回答的问题。
3. **确认编辑批次。** 用表格列出路径及章节、问题、证据、建议编辑、保留方式和引用检查结果。针对列明的编辑请求一次批准。存在语义冲突时，提供具体选择。笼统清理请求不代表批准未展示删除。未跟踪内容和未提交章节需明确保留选择，Git 未必有当前内容。完成本步前，必须明确哪些行已批准，哪些行暂缓。
4. **应用已批准的编辑。** 先核对内容是否仍与批准版本一致。如果中途发生变化，重新确认对应行。原位修订当前正文，在所属文档合并重复规则，修复入链。保留正式 ADR 历史，准确标记替代 / 范围。保留无关改动及已安装副本；安装更新另需授权。未解行只暂停依赖编辑。完成本步前，每个已批准行都应已应用，或明确记录为阻塞；不得应用未批准变化。
5. **验证阅读路径：**检查变更链接、状态、残留引用。重做发现过时规则的搜索，检查命中，不要求历史零命中。从当前导航读替代规则并核范围；历史 ADR 命中应有状态 / 替代，明确旧规则为何不生效。读 diff 检查仍有效约束是否丢失。完成本步前，每个已批准行都必须有预期结果证据，或有具体阻塞报告。
6. **记录结果并收尾。** 在现有工作记录中补充变更路径、验证结果和未解决行。无记录时只建一个 `.rope/issues/<slug>/quick.md`，清单放其中，不为每个发现另建报告。报告简明 diff。仅在任务 / 流程已授权时提交，只含批准变化。

<a id="legacy-glossary-migration"></a>
## 旧术语表迁移

每次都检查 `.rope/CONTEXT.md`，即使用户没点名。按当前加载的 Rope 约定，不发明版本迁移阶梯：

- **只有 CONTEXT：**提议保留全部内容、重命名为 GLOSSARY，同批修复当前入链。
- **两者都有：**比较内容和归属，提议合并进 GLOSSARY。不能覆盖任一文件或默默选择冲突定义；冲突未决时暂停依赖编辑。
- **只有 GLOSSARY：**无需改名，不建根目录术语表、重复词汇表或永久 CONTEXT 别名。

改名与内容清理是不同编辑。长契约、流程、任务证据不会因改名自动成为术语，按 current-docs 提议其正确归属。保留有效约束；删除 / 移动内容仍经正常批次批准。更新活动指令及链接，包括根 Rope 区块；历史提及若描述历史则保留。旧入口删除前，报告无法编辑或范围外的活动消费者。

<a id="examples"></a>
## 示例

- spec 同时说“旧会话保留快照”和“每轮读当前设置”：追踪已接受变更，提议替换旧段及引用。无决定时询问必须保证哪个行为，当前代码不能自动授权契约变化。
- 两指南重复有效规则：规则留所属文档，另一处改链接；Git 保存已提交旧文。
- 已替代 ADR 被 grep 命中：保留历史，标记已替代范围和来源，当前导航指向替代。搜索命中本身不能证明该内容仍是当前有效指令。

<a id="safety-boundary"></a>
## 安全边界

只执行范围内的文档编辑。不得修改产品代码、作出新架构选择、进行全仓格式化、运行 Git reset/clean，或自动更新已安装技能。没有 Git 历史时，保留原内容，直到用户批准保留方式或删除。已批准编辑暴露新冲突时，只将对应行交回用户决定。

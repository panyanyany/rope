# Rope

Rope 是一组代理编码技能。它将需求澄清、切片规划、实现、审查和端到端验收连接起来，并把项目知识保存在仓库的 `.rope/` 目录中。

使用 Rope 需要支持技能和子代理的宿主，例如 pi 或 Claude Code。父编排器负责决策和交接；叶子工作者负责实现、探索、审查或产品操作。长期决定写入文件，供后续会话读取。

本文为中文主文档。[README.zh-CN.md](README.zh-CN.md) 提供相同内容。

<a id="install"></a>
<a id="安装"></a>
## 安装技能

在 shell 中运行以下命令，将完整技能集安装到默认代理技能目录：

```bash
npx git+https://github.com/WufeiHalf/rope.git add
```

如果要安装到项目目录，指定目标路径：

```bash
npx git+https://github.com/WufeiHalf/rope.git add --target ./.agents/skills
```

安装后，在目标仓库中向代理发出以下指令：

```text
调用 rope-init，初始化本仓库的 .rope 知识层。
```

`rope-init` 是技能名称。初始化会创建术语表、导航和知识目录，并保留已有知识。

如需配置叶子工作者使用的模型，再让代理调用 `rope-harness-presets`。每台机器首次配置或模型目录变化时，可以手动刷新预设。预设缺失时，执行流程使用宿主通用工作者，并记录降级原因。

全局目标和项目目标都安装完整技能集及共享参考文档。跨技能引用相对于实际加载的技能目录解析。更新 CLI 后，需要对目标目录再次执行 `add`，才会刷新已复制的技能。如果存在多个同名副本，先确认宿主实际加载的路径。

<a id="how-it-works"></a>
<a id="工作方式"></a>
## 从需求开始交付

向代理描述任务，并调用 `rope-grill`。完整流程如下：

1. **澄清需求（grill）。** 明确用户需要什么行为、失败时看到什么，以及哪些实现方式违背需求。已确认的决定在当轮写入 `.rope/`。代理用 3–6 点回顾对齐目标，沿用已有指令和答案；只有未定的关键取舍需要确认。代理根据风险、不确定性和任务容量选择完整流程或小任务快速路径。
2. **规划切片（shape）。** 将需求写入 issue 包，包含 PRD、切片、行为矩阵和 E2E 计划。代理自行维护切片、依赖图和执行安排，并提供 3–5 点契约摘要。与已授权目标一致时直接继续；只有实质变化和未授权动作需要用户决定。issue 包在授权范围内自动本地提交。每个切片必须能在一个全新上下文窗口内完成。
3. **执行实现（go）。** 父编排器派发就绪切片，叶子工作者在约定测试边界上执行 TDD。宿主支持隔离 worktree 时，必要接口依赖合并后即可派发切片；共享检出目录则按文件归属安排波次。父编排器按顺序合并交付提交。
4. **审查和验收。** 全部切片完成后，两个未参与实现的只读工作者分别检查规范和行为。阻塞问题交给实现者修复；首个无法缩小阻塞集合的轮次需要用户决定。审查通过后，父编排器启动一套共享服务，E2E 执行者通过真实入口验证用户旅程。每个必需项都要有通过证据，或有用户逐项明确豁免。
5. **验证并收尾（finish）。** 检查审查记录、E2E 结果、切片提交、工作树状态和架构证据。满足关闭条件后，更新 issue 状态及已确认的长期文档。

已诊断的小修复或小功能，如果能在一个全新上下文窗口内完成，可以使用 `rope-quick`。该路径由单个代理完成简短澄清、测试、实现、本地提交和文档同步。需要新架构决策、同一修复失败两次、超出范围，或涉及 schema、破坏性及生产操作时，必须停止并返回完整流程。

<a id="what-is-rope"></a>
<a id="rope-是什么"></a>
## 保存项目知识

`.rope/` 保存项目术语、架构决定、稳定契约、已验证事实和当前任务记录。后续会话先读取这些文档，再查相关代码，避免依赖已经丢失的聊天上下文。

父编排器通过简报传递行为契约、约束和证据要求。叶子工作者返回摘要、提交和产物路径。调查事实保存在 `map.md` 中，便于工作者定位代码并修正已经失效的信息。

<a id="what-makes-it-different"></a>
<a id="有什么不一样"></a>
## 理解执行和验收规则

| 规则 | 执行方式 |
| --- | --- |
| 按依赖图安排工作 | shape 从 `Blocked by` 推导就绪集合、各层宽度和最长阻塞链，再给出执行选择。 |
| 控制单个切片的范围 | 每片必须能在一个全新上下文窗口内完成。超出容量时重新拆分；改变需求时返回 grill。 |
| 用契约摘要确认结果 | Contract Note 用 3–5 个单句说明可观察结果。摘要来自行为契约，验收仍依据契约、矩阵及 E2E。 |
| 保留架构约束 | 每个相关决定都记录继承、扩展、取代、例外或不适用的处置。切片通过约束包引用来源。 |
| 分开代码审查和产品操作 | 规范扫描器和行为审查者只读代码及证据。审查通过后，E2E 执行者操作真实产品入口。 |
| 让收尾检查范围明确 | finish 核查记录与证据，不重复代码审查或已经通过的 E2E。 |

<a id="skills"></a>
<a id="技能清单"></a>
## 选择技能

| 技能 | 使用目的 |
| --- | --- |
| `rope-init` | 初始化目标仓库的 `.rope/` 知识层。 |
| `rope-grill` | 澄清需求，记录决定，形成可交给 shape 的行为契约。 |
| `rope-shape` | 编写 PRD、切片、行为矩阵和 E2E 计划，并确认依赖图。 |
| `rope-go` | 派发实现、收集证据、合并切片，完成结束审查和 E2E 验收。 |
| `rope-finish` | 验证记录，关闭 issue，并完成已确认的架构文档更新。 |
| `rope-summary` | 将刚完成工作中的可复用契约和经验写入 `.rope/`。 |
| `rope-clear` | 按已批准批次整理文档，迁移旧布局，并保留正式决策历史。 |
| `rope-quick` | 在单个上下文窗口内完成小任务；触及停止条件时返回完整流程。 |
| `rope-harness-presets` | 将叶子角色绑定到宿主的原生代理预设。 |

<a id="rope-layout"></a>
<a id="rope-布局"></a>
## 查找项目文档

```text
.rope/
  GLOSSARY.md       # 项目术语及定义
  routes.md         # 代码、测试和文档导航
  adr/              # 架构决策记录
  research/         # 已验证的内部或外部事实
  specs/            # 稳定实现契约
  issues/<slug>/
    prd.md          # 行为契约与架构约束
    tasks.md        # 切片状态、行为矩阵和审查结论
    e2e.md          # 真实环境验证计划及结果
    map.md          # 调查事实，每条包含路径和日期
    verify.md       # 收尾验证记录
    quick.md        # 小任务快速路径的记录
```

已有 `.rope/CONTEXT.md` 在迁移前仍可读取。需要迁移时，调用 `rope-clear` 按批准批次合并或改名为 `.rope/GLOSSARY.md`，并修复有效引用。`rope-init` 保留已有术语表，不创建竞争副本。本仓库当前仍使用 `.rope/CONTEXT.md`。

<a id="开发"></a>
## 修改和验证 Rope

修改前读取 [AGENTS.md](AGENTS.md)、[仓库导航](.rope/routes.md)和相关规范。中文文档遵守[内容设计规范](.rope/specs/guides/content-design.md)。

查看 CLI 用法：

```bash
node bin/rope.js --help
```

运行冒烟测试：

```bash
node --test tests/*.test.mjs
```

测试覆盖技能元数据、相对引用和 CLI 安装。技能内容还需要人工检查流程、约束和可移植性。

## 查看历史决定

当前流程的背景保存在 [.rope/adr/](.rope/adr/)。阅读时先检查决定的状态和适用范围。主要变化包括：将验证与实现分开、明确架构决定的处置、增加契约摘要和小任务路径、采用依赖图调度、将真实产品验收从代码审查中分离，以及退役脚本驱动的动态工作流。
